  #13: tab views and group boxes (e3730e1, af0f3ec)

  The capture comparison found three bugs in the earlier M2 pass:

  - Group-box edges were wrong. The Date & Time, Network and Desktop & Screen
    Saver captures all show the same rows. The top is #ababab followed by three
    shadow rows (#c5c5c5, #dbdbdb, #e5e5e5). The sides are #c8c8c8 with an
    #e2e2e2 inner column. The bottom is #e4e4e4 then #dbdbdb, lighter than the
    sides. Silvestris was drawing a #c8c8c8 border with the dark line one row
    inside it, so the top looked doubled, and the bottom matched the sides. One
    painter now draws the measured edges for both GroupBox and TabView, which
    also removes a duplicate. At 200% each row is two device rows.
  - Segmented controls lost their emboss row. The token was measured (#b9b9b9
    under the #5e5e5e edge), but each segment was clipped to its own height,
    which cut the row off. It now shows in all four segmented samples in both
    Aqua appearances.
  - Group-box titles were bold. HIG p. 344 sets them in the small system font.
    Titles can now also be a checkbox or pop-up, which p. 344 allows.

  TabView moved from preferences into controls, gained small and mini tab sizes,
  and now has a gallery sample, a tab-view golden in all four appearances and
  five scales, and six scenario tests. The tests cover:
  - the box line sitting 10 rows below the tab top;
  - the tabs centred on the box;
  - clicks calling the handler while setting the selection in code does not;
  - the 82ce65a overflow and scroll behaviour.

  The old System Preferences placement is kept as preferences::pane_tab_view.
  This is an API change for lotus and johjoh when they move their pin, and it is
  recorded in CHANGELOG.md.

  One small difference remains and is logged in docs/exceptions.md: under the
  tabs we paint #bbbbbb where the capture has #b9b9b9 then #e4e4e4. Fixing it
  would mean changing the emboss token every segmented control shares.

  #16: menus, measured so far

  - Item height: the Arrange By contextual menu uses 18 px items, but the
    menu-bar menu in Finder-Menu.png uses 19 px. Both match an exact grid of 4
    px padding and 12 px separators with the line on the 6th row. So the single
    menu_item_height = 19 token is wrong for contextual and pop-down menus, and
    the menu needs a size it doesn't have.
  - Body colour: the body is translucent white, about 95% opaque. Over the
    toolbar it reads #fbfbfb; over the dark desktop it reads #f2f2f3. The
    current #f2f2f2 token is that dark-background reading baked in as an opaque
    colour.
  - Selection gradient: this matches the existing token in both captures.
