# **Silvestris Geist refinement — implementation plan**

**Target:** `estyseesghosts/silvestris`\
**Branch:** `devel/sil-cocoa-fixture`\
**Verified HEAD:** [`d575f34cb7472f86015c7421998464ea6247ec81`](https://github.com/estyseesghosts/silvestris/commit/d575f34cb7472f86015c7421998464ea6247ec81?utm_source=chatgpt.com)\
**Scope:** Geist Light, Geist Dark, and the theme-resolution infrastructure required to render them correctly.

This plan is based on the source at the verified branch HEAD, not an assumed future implementation. The work should be completed sequentially, with tests and visual inspection at each major checkpoint.

The objective is to make Geist a polished, modern, restrained alternative to Aqua. It must remain a **presentation theme for the existing Silvestris application model**, not become a replacement for the 2009 HIG's structure, interaction rules, or control semantics.

## **Non-negotiable implementation rules**

These apply to every task below.

1. **Aqua is protected.** Neither Aqua Light nor Aqua Dark may change visually as a side effect of Geist work. Existing Aqua assets, gradients, geometry, fonts, spacing, window controls, and animations must remain intact.
2. **Do not redesign application layouts.** Keep HIG window roles, preferences navigation, toolbar structure, source-list hierarchy, menu behaviour, responder-chain semantics, and keyboard interactions.
3. **Do not duplicate components.** A Geist button must use the existing button implementation with Geist styling. The same principle applies to menus, fields, lists, scrollbars, and window frames.
4. **Never introduce consumer-specific styling into the toolkit.** Lotus, Pain, Chaus, and other applications must be able to use Geist without special cases inside Silvestris.
5. **Never use Aqua artwork as the fallback for missing Geist interface artwork.** Provide an appropriate neutral symbol, or an explicit documented fallback. Do not silently produce a hybrid design.
6. **Do not accept regressions as aesthetic compromises.** A prettier scrollbar that loses dragging, a better-looking popup that clips labels, or a rounded window with broken resizing is a failed implementation.
7. **Do not upgrade GPUI, rewrite the windowing system, or change unrelated public APIs.** The repository already pins GPUI in [`Cargo.toml`](https://github.com/estyseesghosts/silvestris/blob/d575f34cb7472f86015c7421998464ea6247ec81/Cargo.toml?utm_source=chatgpt.com). This work should remain compatible with that pin.
8. **Do not freestyle visual choices.** The colours, dimensions, typography, and artwork rules specified below are the initial design contract. Any technical deviation must be documented and visually demonstrated before it is adopted.

The relevant external references are the official [Geist colour system](https://vercel.com/geist/colors?utm_source=chatgpt.com), [typography specifications](https://vercel.com/geist/typography?utm_source=chatgpt.com), and [material guidelines](https://vercel.com/geist/materials?utm_source=chatgpt.com). These establish the visual principles. Their React components and web layout patterns are **not** to be copied into Silvestris.&#x20;

## **Target visual specification**

These are implementation values, not choices left to the implementer.

### **Colour palette**

The following is the proposed Silvestris adaptation of Geist's semantic colour hierarchy. It is deliberately not presented as an exact reproduction of every Vercel colour token.

| Role                        | Geist Dark | Geist Light |
| --------------------------- | ---------- | ----------- |
| Document/content background | `#000000`  | `#FFFFFF`   |
| Window, titlebar, sidebar   | `#0A0A0A`  | `#FAFAFA`   |
| Group/raised surface        | `#111111`  | `#FFFFFF`   |
| Control background          | `#171717`  | `#FFFFFF`   |
| Control hover               | `#1F1F1F`  | `#FAFAFA`   |
| Control pressed             | `#292929`  | `#F2F2F2`   |
| Default border              | `#262626`  | `#E6E6E6`   |
| Hover border                | `#393939`  | `#C9C9C9`   |
| Strong border               | `#505050`  | `#8F8F8F`   |
| Primary text                | `#EDEDED`  | `#171717`   |
| Secondary text              | `#A1A1A1`  | `#666666`   |
| Disabled text               | `#878787`  | `#8F8F8F`   |
| Focus/accent                | `#0095FF`  | `#0070F3`   |
| Selected list background    | `#0B3A5C`  | `#E6F1FE`   |
| Primary action background   | `#EDEDED`  | `#171717`   |
| Primary action text         | `#000000`  | `#FFFFFF`   |

The intended appearance is predominantly black or near-black in Dark, with clear but subtle separation between surfaces.

Do not make every surface pure black. That would destroy the depth hierarchy and cause controls to disappear.

Equally, do not brighten every window and panel to `#171717`. That would recreate the current problem.

### **Geometry**

| Element                 | Geist target                                   |
| ----------------------- | ---------------------------------------------- |
| Standard button         | 4px corner radius                              |
| Toolbar/textured button | 4px                                            |
| Segmented control       | 4px outer radius                               |
| Popup/select control    | 4px                                            |
| Normal text field       | 4px                                            |
| Search field            | 6px                                            |
| Checkbox                | 3px                                            |
| Menu/popover            | 6px                                            |
| Group panel             | 6px                                            |
| Floating window         | 6px target, subject to native compositor shape |
| Scrollbar thumb         | Fully rounded ends                             |
| Radio button            | Remains circular                               |
| Installer Continue      | Remains circular                               |

These values are for Geist only. Explicitly circular controls are not to be squared off, and Aqua's established radii must not be changed.

### **Typography**

Use Geist Sans for interface text and Geist Mono for monospaced text.

| Typography role           | Target         |
| ------------------------- | -------------- |
| Regular interface         | 13px           |
| Small interface           | 12px           |
| Mini interface            | 11px           |
| Window title              | 13px           |
| Section heading           | 12px, semibold |
| Menu text                 | 13px           |
| List/table text           | 13px           |
| Toolbar label             | 11px           |
| Monospaced interface text | 12px           |

Normal interface text should be regular weight. Standard action labels may use medium weight where needed; headings should use semibold. Avoid excessive bold text.

These values retain Silvestris's compact desktop character while correcting especially small labels. They are not permission to enlarge the overall UI.

## **Phase I — Protect the existing implementation**

### **Task 1 — Freeze the source baseline and define the allowable change surface**

**Source:** [`silvestris-core/src/lib.rs`, theme resolver](https://github.com/estyseesghosts/silvestris/blob/d575f34cb7472f86015c7421998464ea6247ec81/crates/silvestris-core/src/lib.rs?utm_source=chatgpt.com#L23-L56), [`theme.rs`, theme state and font overrides](https://github.com/estyseesghosts/silvestris/blob/d575f34cb7472f86015c7421998464ea6247ec81/crates/silvestris/src/theme.rs?utm_source=chatgpt.com#L35-L123).

**Deliverables:**

- Record the starting commit, branch, GPUI pin, and current four-theme configuration in `docs/geist-refinement.md`.
- Record the existing Aqua typography and metrics before modifying any shared theme structure.
- Identify which changes belong in `silvestris-core`, which belong in GPUI renderers, and which belong in font registration.
- Establish the rule that `aqua.rs` is read-only for this project unless a shared type requires a purely mechanical field addition.
- If a shared theme structure gains a field, initialize Aqua with values that preserve its existing output exactly.
- Require every new theme-specific rendering decision to use the resolved `ThemeId` or theme tokens, rather than application names or operating-system assumptions.

**Avoid:**

- Changing the public meaning of `ThemeFamily`, `ThemeId`, or `ThemePreference`.
- Introducing a separate Geist widget crate.
- Changing the default theme preference or consumer configuration.
- Mixing theme selection with operating-system appearance detection.

**Regression traps:**

- `ThemePreference::resolve()` must continue to honour system and explicitly selected appearances.
- Global font overrides and per-theme font overrides must retain their existing precedence.
- Theme switching must continue to refresh windows without recreating application state.

**Completion gate:** The project builds, all existing tests pass, and the baseline is documented.

### **Task 2 — Establish an enforceable Aqua visual baseline**

**Source:** [`docs/goldens.md`](https://github.com/estyseesghosts/silvestris/blob/d575f34cb7472f86015c7421998464ea6247ec81/docs/goldens.md?utm_source=chatgpt.com), [`tests/goldens.rs`](https://github.com/estyseesghosts/silvestris/blob/d575f34cb7472f86015c7421998464ea6247ec81/crates/silvestris/tests/goldens.rs?utm_source=chatgpt.com).

**Deliverables:**

- Run the existing golden renderer against the clean source baseline.
- Preserve Aqua Light and Aqua Dark captures at 100%, 125%, 150%, 175%, and 200% scale.
- Preserve the current Geist captures separately as *before* references. They are not the desired final appearance.
- Ensure the captured controls cover buttons, fields, checkboxes, radio buttons, segmented controls, popup controls, menus, scrollbars, source lists, tables, toolbars, preferences, and window frames.
- Capture actual Windows 11 windows in addition to offscreen goldens. Include active and inactive windows, maximized and floating windows, and all four themes.
- Record existing differences and failures before beginning changes. Do not classify existing defects as regressions introduced by the refinement.

Run the existing commands documented by the repository, including:

```
pwsh tools/metrology/render.ps1
python tools/metrology/gate.py --candidate target/goldens
cargo test -p silvestris --test goldens
```

**Avoid:**

- Regenerating accepted Aqua images merely because the candidate render differs.
- Running the acceptance tool with `--accept` automatically.
- Replacing historical Aqua references with Geist screenshots.
- Comparing screenshots at mismatched scale factors.

**Regression traps:**

- Font registration changes may produce silent substitutions.
- Rounded borders can develop one-pixel differences at fractional scaling.
- Offscreen rendering does not prove that native window transparency is correct.

**Completion gate:** Baseline test results and screenshots are saved. Later changes must be compared against these exact references.

### **Task 3 — Add explicit theme-isolation tests**

**Source:** [`silvestris-core/src/lib.rs`, conformance tests](https://github.com/estyseesghosts/silvestris/blob/d575f34cb7472f86015c7421998464ea6247ec81/crates/silvestris-core/src/lib.rs?utm_source=chatgpt.com#L58-L150), [`silvestris-core/tests/font_overrides.rs`](https://github.com/estyseesghosts/silvestris/blob/d575f34cb7472f86015c7421998464ea6247ec81/crates/silvestris-core/tests/font_overrides.rs?utm_source=chatgpt.com).

**Deliverables:**

- Add tests confirming that Aqua Light and Aqua Dark resolve to their original font families, metrics, colours, and control materials.
- Store fixture snapshots of resolved Aqua tokens, rather than comparing against constants calculated by the newly modified code.
- Assert that changing Geist's palette or metrics does not change resolved Aqua tokens.
- Test all four theme IDs and both global and per-theme font overrides.
- Add a theme-switching sequence: Aqua Light → Geist Dark → Geist Light → Aqua Dark → Aqua Light.
- Confirm that the final Aqua appearance matches the original baseline and that the application state has not been reset.
- Separate expected Geist golden differences from forbidden Aqua differences in test reporting.

**Avoid:**

- Self-referential tests where the expected values are obtained from the implementation under test.
- Broadly weakening screenshot comparison tolerances.
- Adding exceptions to conformance tests merely to make new Geist colours pass.

**Regression traps:**

- Shared constructors can unintentionally change Aqua's geometry.
- Globally registered fonts can change fallback order.
- Caches may retain appearance-specific artwork after a theme switch.

**Completion gate:** A genuine Geist-to-Aqua visual or token regression causes a test failure.

## **Phase II — Correct the typography and theme foundations**

### **Task 4 — Bundle Geist Sans properly and remove Inter as Geist's default**

**Source:** [`silvestris-fonts/src/lib.rs`](https://github.com/estyseesghosts/silvestris/blob/d575f34cb7472f86015c7421998464ea6247ec81/crates/silvestris-fonts/src/lib.rs?utm_source=chatgpt.com#L34-L91), [`silvestris-core/src/lib.rs`](https://github.com/estyseesghosts/silvestris/blob/d575f34cb7472f86015c7421998464ea6247ec81/crates/silvestris-core/src/lib.rs?utm_source=chatgpt.com#L23-L30), [`tools/fonts/manifest.py`](https://github.com/estyseesghosts/silvestris/blob/d575f34cb7472f86015c7421998464ea6247ec81/tools/fonts/manifest.py?utm_source=chatgpt.com#L18-L58).

The repository currently uses Inter for Geist's normal interface text. This must change.

**Deliverables:**

- Obtain Geist Sans from the official [Vercel Geist font releases](https://github.com/vercel/geist-font/releases?utm_source=chatgpt.com). Prefer the same pinned release, `v1.9.2`, already recorded for Geist Mono, rather than silently upgrading both families.
- Select static TTF faces for Regular 400, Medium 500, SemiBold 600, Bold 700, and Regular Italic if available. Do not use a variable face unless the pinned GPUI text system demonstrably supports its weight selection correctly.
- Inspect the font's internal family names with the existing `tools/fonts/sfnt_names.py` tooling. Register the actual embedded family name rather than assuming the filename matches it.
- Add the fonts to `crates/silvestris-fonts/fonts/geist-sans/`.
- Add `GEIST_SANS` constants in both the font crate and the GPUI-free core, keeping the string values consistent.
- Register the faces in `FACES`, include the family in `FAMILIES`, and include its OFL license in `LICENSES`.
- Extend `tools/fonts/manifest.py` with the source release, license, archive hash, and individual font metadata. Regenerate and verify the manifest.
- Modify only Geist's `typography()` to use Geist Sans.
- Retain Inter as an explicitly supported auxiliary family for this pass if removing it would break consumers. It must no longer be Geist's default.

**Avoid:**

- Downloading fonts at runtime.
- Depending on a system-installed font.
- Renaming or altering licensed font files without first verifying the license requirements.
- Modifying Aqua's Lato or Source Code Pro registrations.
- Assuming that successful font registration proves the actual text renderer selected the requested face.

**Regression traps:**

- Windows and Linux may report family names differently if internal font metadata is mishandled.
- Font weight selection may silently synthesize bold.
- Text widths, cursor positions, wrapping, and glyph baselines will change.
- A previously supported consumer font override must still work.

**Completion gate:** All expected Geist Sans faces are registered, verified and visibly used; Aqua still uses its original faces.

### **Task 5 — Establish the new Geist typography metrics**

**Source:** [`geist.rs`, typography and metrics](https://github.com/estyseesghosts/silvestris/blob/d575f34cb7472f86015c7421998464ea6247ec81/crates/silvestris-core/src/geist.rs?utm_source=chatgpt.com#L41-L136), [`tokens.rs`, Typography](https://github.com/estyseesghosts/silvestris/blob/d575f34cb7472f86015c7421998464ea6247ec81/crates/silvestris-core/src/tokens.rs?utm_source=chatgpt.com#L84-L102).

**Deliverables:**

- Implement the typography sizes in the specification above, in `geist.rs` only.
- Keep regular text at 13px initially. Improve small and mini text to 12px and 11px respectively.
- Use semibold 600 for section headings in Geist. Preserve Aqua's existing heading weights.
- Preserve monospaced styling only where content genuinely needs it: code, terminal-like content, numerical technical fields, or explicitly requested monospace labels.
- Verify text vertical alignment against actual control bounds. Text must be optically centred, not shifted by arbitrary one-pixel patches.
- Record measured label widths and heights for the main control sizes at all five scaling factors.
- Check Latin letters, digits, punctuation, ellipses, path names, and strings containing accented characters.
- Ensure settings descriptions can wrap without being clipped by fixed-height controls or containers.

**Avoid:**

- Replacing all fonts with Geist Mono.
- Applying the same font size to all typography roles.
- Adding global line-height overrides.
- Changing HIG window dimensions to compensate for bad text metrics.
- Compensating for one incorrectly aligned control by changing a global font baseline.

**Regression traps:**

- Preferences category labels have a hardcoded 13px line height.
- Toolbar labels and source-list headings have tighter available space than ordinary body text.
- Popups calculate natural dimensions based on text measurements.
- Text cursor and selection geometry must agree with the new font.

**Completion gate:** Geist text is legible, properly aligned, and unclipped across all standard control sizes and both appearances.

### **Task 6 — Introduce a proper Geist colour palette instead of scattered hex literals**

**Source:** [`geist.rs`, current colour definitions](https://github.com/estyseesghosts/silvestris/blob/d575f34cb7472f86015c7421998464ea6247ec81/crates/silvestris-core/src/geist.rs?utm_source=chatgpt.com#L173-L310), [`tokens.rs`, semantic colour roles](https://github.com/estyseesghosts/silvestris/blob/d575f34cb7472f86015c7421998464ea6247ec81/crates/silvestris-core/src/tokens.rs?utm_source=chatgpt.com#L104-L171).

**Deliverables:**

- Define a private `GeistPalette` structure within `silvestris-core`, preferably in `geist.rs` or a narrowly scoped `geist/palette.rs`.
- Provide explicit `dark()` and `light()` constructors containing the colour values in the visual specification.
- Organize the palette into meaningful roles: window backgrounds, surfaces, control states, borders, text, selection, accents, and semantic feedback.
- Keep `Theme::colors` as the public semantic interface consumed by Silvestris controls.
- Resolve the Geist palette into the existing `Colors`, `Controls`, `Lists`, and `ChromeSet` tokens.
- Where an existing colour role is insufficient, add a narrowly defined role rather than making a renderer infer styling from unrelated colours.
- Replace duplicated hex literals in `geist_dark()` and `geist_light()` with named palette references.
- Preserve explicit alpha only where transparency is actually needed: shadows, scrims, or overlays.
- Add unit tests for the resolved palette values, including selected, disabled, active, and inactive states.

The palette should follow Geist's hierarchy: backgrounds, ordinary component surfaces, borders, high-contrast surfaces, and text.

**Avoid:**

- Adding the Geist palette to `aqua.rs`.
- Replacing the existing `Colors` contract with a completely different public API.
- Putting palette values directly in individual GPUI controls.
- Using alpha overlays as the default method for producing neutral borders.
- Creating a generic CSS-style theming engine.
- Having separate, competing palette definitions in Silvestris and its demo application.

**Regression traps:**

- Semantically identical surfaces must resolve to identical colours across components.
- Inactive-window colours must not inadvertently change the selected theme.
- Alpha compositing against different parents must not change the intended colour.
- Existing consumer font and theme overrides must continue working.

**Completion gate:** Geist resolves through one coherent palette definition, with no uncontrolled hardcoded Geist surface colours scattered across renderers.

### **Task 7 — Implement the new Geist Dark surface hierarchy**

**Source:** [`geist.rs`, Dark colours and chrome](https://github.com/estyseesghosts/silvestris/blob/d575f34cb7472f86015c7421998464ea6247ec81/crates/silvestris-core/src/geist.rs?utm_source=chatgpt.com#L256-L333), [`chrome.rs`, window background](https://github.com/estyseesghosts/silvestris/blob/d575f34cb7472f86015c7421998464ea6247ec81/crates/silvestris/src/chrome.rs?utm_source=chatgpt.com#L521-L563).

**Deliverables:**

Apply the following precise surface relationships:

- Document/content surfaces: `#000000`.
- Main application window, titlebar, toolbar, bottom bar, and sidebar: `#0A0A0A`.
- Raised preference groups and inset organizational surfaces: `#111111` where a separate surface is required.
- Standard controls: `#171717`, with `#1F1F1F` hover and `#292929` pressed states.
- Ordinary dividers: `#262626`.
- Borders around floating or interactive elements: `#393939` when stronger separation is required.

The window and toolbar should generally read as one continuous dark surface. Do not use a lighter rectangular strip just because the original Aqua toolbar has a separate material.

Retain thin separators where the HIG layout needs them. Avoid visible divider lines where two adjacent regions already have sufficient contrast.

The titlebar, sidebar, content area, and preferences pane must all use semantic colours consistently.

When the window becomes inactive, reduce emphasis using the existing inactive chrome roles. Do not make the entire window obviously lighter.

**Avoid:**

- Making the whole interface one uniform `#000000` block.
- Using `#1A1A1A` as the default window background.
- Adding a gradient to make dark surfaces appear raised.
- Using bright borders to separate every control.
- Changing how the window is laid out.

**Regression traps:**

- Black content surfaces must not become indistinguishable from text fields or panels.
- Transparent scrollbars and popups must still render visibly.
- Inactive titlebars must not look like disabled application windows.
- Aqua chrome must remain unchanged.

**Completion gate:** Geist Dark has a clearly black foundation and subtle, consistent surface hierarchy.

### **Task 8 — Bring Geist Light into the same semantic system**

**Source:** [`geist.rs`, Geist Light implementation](https://github.com/estyseesghosts/silvestris/blob/d575f34cb7472f86015c7421998464ea6247ec81/crates/silvestris-core/src/geist.rs?utm_source=chatgpt.com#L420-L660).

Geist Light already has several reasonable values. It needs consistency more than radical alteration.

**Deliverables:**

- Keep the primary window background `#FAFAFA`.
- Use white `#FFFFFF` for document surfaces, fields, and raised groups.
- Use `#F2F2F2` for pressed or selected neutral controls.
- Use `#E6E6E6` for ordinary borders.
- Use `#C9C9C9` for stronger or hovered borders.
- Keep primary text `#171717` and secondary text `#666666`.
- Keep the primary interactive accent `#0070F3`.
- Ensure popup menus, scrollbars, toolbars, and inactive windows use the same palette resolution structure as Geist Dark.
- Give Light the same typography and geometry as Dark.

Use the same `GeistPalette` roles introduced in Task 6. Light should not need its own independent collection of component recipes.

**Avoid:**

- Introducing bright blue borders on ordinary controls.
- Making all light surfaces visibly grey.
- Adding Aqua-style gloss.
- Using a second set of spacing rules for Light.
- Treating Light as a derivative that can be tested less thoroughly.

**Regression traps:**

- Dark and Light must have identical component sizes.
- Focus states must remain visible on white.
- Inactive or disabled controls must not become invisible.
- Theme switching must not retain colours from the previous appearance.

**Completion gate:** Both Geist appearances are structurally identical and differ only where their colour palettes require it.

### **Task 9 — Rebuild Geist's control-state colours coherently**

**Source:** [`geist.rs`, buttons and selection states](https://github.com/estyseesghosts/silvestris/blob/d575f34cb7472f86015c7421998464ea6247ec81/crates/silvestris-core/src/geist.rs?utm_source=chatgpt.com#L174-L256), [`tokens.rs`, BevelStates](https://github.com/estyseesghosts/silvestris/blob/d575f34cb7472f86015c7421998464ea6247ec81/crates/silvestris-core/src/tokens.rs?utm_source=chatgpt.com#L198-L233), [`silvestris-core/src/lib.rs`, contrast conformance](https://github.com/estyseesghosts/silvestris/blob/d575f34cb7472f86015c7421998464ea6247ec81/crates/silvestris-core/src/lib.rs?utm_source=chatgpt.com#L58-L147).

**Deliverables:**

For ordinary Geist Dark controls, enforce this state table:

| State             | Fill      | Border    | Text      |
| ----------------- | --------- | --------- | --------- |
| Normal            | `#171717` | `#262626` | `#EDEDED` |
| Hover             | `#1F1F1F` | `#393939` | `#EDEDED` |
| Pressed           | `#292929` | `#505050` | `#EDEDED` |
| Selected, neutral | `#292929` | `#505050` | `#EDEDED` |
| Disabled          | `#111111` | `#262626` | `#878787` |

For Geist Light, use the corresponding palette roles defined above.

The primary action button is the exception: Dark uses a light fill with dark text; Light uses a dark fill with white text.

Blue should normally mean focus, selection, a link, a progress indication, or a meaningful interactive state. It should not be applied decoratively to every popup arrow or button cap.

Ensure that selected list rows remain distinct from the neutral pressed state.

Extend contrast tests to cover actual text/background pairs, including hover and selected states. The primary target is at least 4.5:1 for ordinary text. Disabled text may follow the existing documented exemption, but should remain visually legible.

**Avoid:**

- Making hover and selected states identical in meaning.
- Using opacity reduction as the only disabled treatment.
- Displaying white text on a bright accent without testing contrast.
- Applying a full blue fill to every selected control.
- Changing how disabled commands are dispatched.

**Regression traps:**

- Checkbox marks must remain visible against selected fills.
- Default-button text colour must invert correctly.
- Focus rings must remain distinct from hover borders.
- Active and inactive source-list selections must be distinguishable.

**Completion gate:** Every common control state is visually recognizable in Geist Light and Dark.

## **Phase III — Remove Aqua-specific visual assumptions from the shared controls**

### **Task 10 — Make corner geometry genuinely theme-resolved**

**Source:** [`tokens.rs`, Metrics](https://github.com/estyseesghosts/silvestris/blob/d575f34cb7472f86015c7421998464ea6247ec81/crates/silvestris-core/src/tokens.rs?utm_source=chatgpt.com#L490-L594), [`segmented.rs`, capsule calculation](https://github.com/estyseesghosts/silvestris/blob/d575f34cb7472f86015c7421998464ea6247ec81/crates/silvestris/src/controls/segmented.rs?utm_source=chatgpt.com#L203-L216), [`text_field.rs`, search field radius](https://github.com/estyseesghosts/silvestris/blob/d575f34cb7472f86015c7421998464ea6247ec81/crates/silvestris/src/controls/text_field.rs?utm_source=chatgpt.com#L693-L709).

**Deliverables:**

- Add explicit theme-resolved geometry for standard text fields, search fields, and rounded segmented controls.
- Use a simple corner policy when the existing height-dependent Aqua capsule must be preserved. For example, a GPUI-free `CornerRule` with `Capsule` and `Fixed(f32)` variants.
- Configure Aqua's rounded segments and search fields to retain their current half-height capsule behaviour.
- Configure Geist segmented controls to use a fixed 4px radius.
- Configure Geist normal text fields to use 4px and search fields to use 6px.
- Update the affected renderers to resolve corner geometry from these metrics.
- Keep radii clamped to valid bounds for unusually short controls.
- Ensure corner clipping and focus-ring geometry use the same resolved radius.

**Avoid:**

- Replacing all `height / 2` calculations globally.
- Making circular controls square.
- Adding special cases based on labels or control IDs.
- Embedding Geist-specific numerical constants directly in control files.
- Extending `Metrics` with a large unrelated design system.

**Regression traps:**

- Segmented-control separators must still reach the outer contour.
- Search-field focus rings must not retain capsule geometry after the field becomes rectangular.
- Fractional scale factors can cause clipped or asymmetric corners.
- Aqua's original pill-shaped elements must remain pixel-identical.

## **Implementation boundaries and stopping conditions**

This is one bounded refinement project, not a mandate to rewrite Silvestris.

The dependency order matters: **protect Aqua → install fonts → establish palettes → correct control geometry and materials → implement scrollbars and artwork → fix native window composition → test and review.**

The implementer should create checkpoints after the font/palette work, control refinement, scrollbar/artwork work, and window-corner work. Each checkpoint must have passing functional tests and Geist/Aqua screenshots. Do not stack several unverified changes and attempt to debug their visual effects at the end.

The work should stop and be reported for review if any of the following happens:

- An Aqua golden changes for a reason other than an explicitly authorized shared rendering correction.
- A Geist design decision cannot be implemented with the stated values without breaking component behaviour.
- A native window issue requires changing GPUI or platform window management outside this scope.
- A control needs a new public API that breaks existing consumers.
- Visual comparison is inconclusive because the test environment cannot reproduce the required scale or compositor behaviour.

**The expected result is not a perfect recreation of Vercel's web interface.** It is a modern Geist appearance applied coherently to Silvestris's existing HIG-based components. The measure of success is that the same application feels convincingly Aqua or convincingly Geist without changing what the application is, how it is structured, or how it behaves.
