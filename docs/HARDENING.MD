I re-checked the branch head; it is still `30173a5860`. I would harden this in the order below. The sequence matters: first make the shared list/model invariants correct, then make virtualization actually scale, then clean up filesystem lifetime and async mutation behavior, and only after that tighten secondary UI behavior and stress coverage.

1. **P0 — Make `ListController` maintain valid, scalable selection state.**  
   **Why this is incorrect:** `ListController::set_items()` replaces the entire item set but blindly preserves `selected` and `anchor`. That only works if every selected ID still exists after reload. Real filesystem operations break that assumption: rename changes a path-derived ID; delete/trash removes it entirely. At the same time, `is_selected()` and `selected_items()` repeatedly scan a `Vec<ItemId>`, so large multi-selections become expensive. `selected_items()` is effectively O(visible × selected), and FilePanel asks for selected entries during rendering. [binding.rs 317–545](https://github.com/estyseesghosts/silvestris/blob/30173a5860ad263feacb3d417a73c3a354a21e78/crates/silvestris/src/binding.rs#L317-L545) [model reload/apply](https://github.com/estyseesghosts/silvestris/blob/30173a5860ad263feacb3d417a73c3a354a21e78/crates/silvestris/src/file_panel/model.rs#L355-L425)  
   **Deliverables:** keep ordered selection semantics, but add efficient membership/index structures; prune vanished IDs whenever items are replaced; clear or repair an invalid anchor; ensure `selected()`, `selected_items()`, `visible_index_of()` and `is_selected()` no longer rely on repeated linear scans where avoidable. Add tests for reload where selected IDs disappear, partial multiple-selection survival, and large selection sets.  
   **Avoidables:** do not simply clear all selection on every reload; surviving IDs are deliberately supposed to remain selected. Do not replace the ordered selection vector with only a `HashSet`, because the current API uses selection order and the last item as the lead.  
   **Regression traps:** Shift-selection anchor semantics, Command/Control toggling, selection order, `select_all()`, and the existing “reload keeps selection by ID” contract must survive. That existing test currently covers only the easy case where the ID still exists. [existing reload test](https://github.com/estyseesghosts/silvestris/blob/30173a5860ad263feacb3d417a73c3a354a21e78/crates/silvestris/tests/file_panel_model.rs#L160-L185)

2. **P0 — Make `IconGrid` genuinely viewport-virtualized.**  
   **Why this is incorrect:** the grid uses `uniform_list`, but `render()` first calls `visible_items()` and constructs `(ItemId, SharedString)` for every item. A 30,000-file directory therefore performs O(n) traversal and cloning every time the icon view renders, before virtualization even starts doing useful work. [icon_grid.rs 335–505](https://github.com/estyseesghosts/silvestris/blob/30173a5860ad263feacb3d417a73c3a354a21e78/crates/silvestris/src/controls/icon_grid.rs#L335-L505)  
   **Deliverables:** have the `uniform_list` range callback resolve only the items needed for visible rows. Add a small indexed controller API if necessary, such as indexed visible-item/ID access, rather than snapshotting the complete list. Ensure labels, IDs and icons are materialized only for cells being built. Add a 30k-entry icon-view stress test equivalent to the existing table test. [current 30k test only exercises table rows](https://github.com/estyseesghosts/silvestris/blob/30173a5860ad263feacb3d417a73c3a354a21e78/crates/silvestris/tests/open_panel.rs#L323-L362)  
   **Avoidables:** do not “fix” this by caching a second 30k-item vector inside `IconGrid`; that merely trades frame CPU for duplicated state and invalidation complexity. The controller should remain authoritative.  
   **Regression traps:** responsive column-count changes, inline rename, selection highlighting, double-click activation, context-menu selection, and scrolling must continue to operate against the correct visible index.

3. **P0 — Remove per-comparison string allocation from file search and sorting.**  
   **Why this is incorrect:** name sorting calls `to_lowercase()` on both names inside the comparator. Sorting n items invokes that comparator O(n log n) times, producing large numbers of temporary strings. Search similarly lowercases every filename every time the user changes the search field. The generic `sort_by_text()` path has the same issue. [panel.rs 860–944](https://github.com/estyseesghosts/silvestris/blob/30173a5860ad263feacb3d417a73c3a354a21e78/crates/silvestris/src/file_panel/panel.rs#L860-L944) [panel duplicate sort path](https://github.com/estyseesghosts/silvestris/blob/30173a5860ad263feacb3d417a73c3a354a21e78/crates/silvestris/src/file_panel/panel.rs#L1515-L1545)  
   **Deliverables:** establish one normalized name key per file entry/listing rather than producing it inside every comparator; use that same key for filename filtering and name sorting. If this belongs below `FileEntry`, make it an implementation detail rather than leaking search-specific state into consumers. Update the generic text sort path so it does not encourage repeated transformation inside comparisons.  
   **Avoidables:** do not debounce ordinary local search as the primary fix. Debouncing can be useful later, but it hides rather than fixes needless O(n)/allocation cost. Do not change displayed filenames to normalized text.  
   **Regression traps:** case-insensitive ordering, Unicode names, folders-first ordering, hidden-file filtering, and the current sort directions need tests. Be explicit about whether normalization is simple lowercase matching or stronger Unicode case folding; do not accidentally change semantics while optimizing.

4. **P1 — Establish one authoritative sort state for the whole file panel.**  
   **Why this is incorrect:** FilePanel has its own `self.sort`, while `TableView` separately owns `(column, direction)`. Clicking a table header updates the table/controller and emits `TableEvent::Sorted`, but FilePanel ignores that event. Conversely, FilePanel context-menu sorting updates its own state/controller without synchronizing the table's sort state. Column view then sorts through `FilePanel::sort_entries()`. The UI can therefore disagree with itself. [FilePanel ignores `Sorted`](https://github.com/estyseesghosts/silvestris/blob/30173a5860ad263feacb3d417a73c3a354a21e78/crates/silvestris/src/file_panel/panel.rs#L462-L475) [TableView header sorting](https://github.com/estyseesghosts/silvestris/blob/30173a5860ad263feacb3d417a73c3a354a21e78/crates/silvestris/src/controls/table_view.rs#L960-L984) [FilePanel's separate sorter](https://github.com/estyseesghosts/silvestris/blob/30173a5860ad263feacb3d417a73c3a354a21e78/crates/silvestris/src/file_panel/panel.rs#L1515-L1545)  
   **Deliverables:** define a single panel sort model containing key + direction. Header events update it; menu commands update it; list, icon and column views consume it. Switching views must preserve exactly the same ordering. The table should expose/apply sort presentation state rather than independently owning a conflicting policy.  
   **Avoidables:** do not solve this by suppressing `TableEvent::Sorted` or disabling header sorting. Do not have each view translate sort rules independently.  
   **Regression traps:** folders-first behavior, ascending/descending toggles, switching list → columns → list, sorting newly loaded column children, and persisted panel state.

5. **P1 — Fix filesystem identity semantics around rename and replacement.**  
   **Why this is incorrect:** `StdFsProvider` gives IDs to interned paths. That means an item's identity effectively changes when its path changes. Rename therefore interacts badly with “selection survives by ID”: the renamed file receives a different ID after relisting, while the old one can remain selected unless Task 1 prunes it. The old path mapping also stays interned. [FsState path↔ID interning](https://github.com/estyseesghosts/silvestris/blob/30173a5860ad263feacb3d417a73c3a354a21e78/crates/silvestris/src/file_panel/std_fs/mod.rs#L69-L99)  
   **Deliverables:** explicitly define the identity contract. For local filesystem entries, either preserve the existing location ID across a successful rename by updating the intern maps, or deliberately issue a new ID and make the mutation result tell the model which new ID replaces the old one. I prefer preserving the provider handle when Silvestris itself performs the rename; external changes can still appear as remove/add.  
   **Avoidables:** do not base identity on display strings. Do not blindly canonicalize everything: symlinks and path semantics are intentionally meaningful here.  
   **Regression traps:** case-only renames on Windows/macOS, rename into the same pathname, symlinks, directories whose descendants are already interned, and collision failures.

6. **P1 — Bound `StdFsProvider`'s interned-path lifetime.**  
   **Why this is incorrect:** both `paths` and `ids` grow monotonically. `list_directory()` interns every returned child, and the provider documentation recommends retaining the provider for the application lifetime. A long Chaus session—or especially a future file manager—can therefore retain every path it has ever browsed. [provider lifetime and maps](https://github.com/estyseesghosts/silvestris/blob/30173a5860ad263feacb3d417a73c3a354a21e78/crates/silvestris/src/file_panel/std_fs/mod.rs#L69-L99) [listing interns every child](https://github.com/estyseesghosts/silvestris/blob/30173a5860ad263feacb3d417a73c3a354a21e78/crates/silvestris/src/file_panel/std_fs/mod.rs#L406-L520)  
   **Deliverables:** introduce explicit retention rules. Keep roots, places, current locations, navigation history and currently exposed entries alive; allow cold transient entry mappings to be reclaimed. A bounded/LRU-style cache is reasonable if handles are documented as session-local. Add a stress test that visits many synthetic directories and asserts state growth is bounded.  
   **Avoidables:** do not casually invalidate location handles still held by panel history, results, column caches or consumers. Do not put weak references everywhere without defining who owns a live location.  
   **Regression traps:** Back/Forward navigation, currently selected entries, open panel outcomes, column view, save destinations, and consumer calls to `resolve()` after the panel closes.

7. **P1 — Make filesystem mutations return useful results and surface failures.**  
   **Why this is incorrect:** inline rename starts an async provider operation and then does `let _ = task.await`; regardless of success, the code reloads. Permission errors, vanished volumes and race-condition collisions become a filename snapping back with no explanation. The table, icon grid and column browser duplicate this pattern. [icon rename](https://github.com/estyseesghosts/silvestris/blob/30173a5860ad263feacb3d417a73c3a354a21e78/crates/silvestris/src/file_panel/panel.rs#L1478-L1512) [table rename](https://github.com/estyseesghosts/silvestris/blob/30173a5860ad263feacb3d417a73c3a354a21e78/crates/silvestris/src/file_panel/panel.rs#L1785-L1815) [column rename](https://github.com/estyseesghosts/silvestris/blob/30173a5860ad263feacb3d417a73c3a354a21e78/crates/silvestris/src/file_panel/panel.rs#L1348-L1418)  
   **Deliverables:** centralize rename/mutation execution in FilePanel instead of three nearly identical callbacks. On success, reload and restore/select the resulting entry. On failure, preserve a coherent selection, report the provider's `FileError`, and avoid pretending the mutation succeeded. Consider returning the resulting `LocationId` from `rename` for explicit reconciliation.  
   **Avoidables:** do not let widgets themselves become filesystem-aware. `TableView`, `IconGrid` and `ColumnBrowser` should only report editing intent; FilePanel/provider remain responsible for I/O.  
   **Regression traps:** inline editor focus, Escape/cancel, Return/commit, rename from context menu, successful rename selection, rapidly closing the panel while a mutation is pending, and stale async completions.

8. **P1 — Reduce eager filesystem work without weakening correctness.**  
   **Why this needs hardening:** filesystem work is correctly off the GPUI thread, which should stay that way, but every directory load eagerly does `file_type`, metadata, modification time, size, symlink target metadata, normalization and full sorting before the panel receives anything. Slow/network directories can therefore leave the chooser showing “loading” much longer than necessary. [background execution](https://github.com/estyseesghosts/silvestris/blob/30173a5860ad263feacb3d417a73c3a354a21e78/crates/silvestris/src/file_panel/std_fs/mod.rs#L215-L230) [eager listing work](https://github.com/estyseesghosts/silvestris/blob/30173a5860ad263feacb3d417a73c3a354a21e78/crates/silvestris/src/file_panel/std_fs/mod.rs#L406-L520)  
   **Deliverables:** profile first, then split cheap enumeration from optional metadata enrichment where it pays off. Name/type/navigation-critical information should arrive first; expensive size/date/link metadata can be enriched asynchronously if required. Keep generation/cancellation semantics so late enrichment cannot contaminate a different directory.  
   **Avoidables:** do not move any of this back onto the UI thread. Do not make rows visibly reshuffle several times unless sorting policy explicitly requires metadata that has not arrived yet. Do not optimize local SSD behavior at the expense of network/removable filesystem correctness.  
   **Regression traps:** symlink classification, broken-link warnings, package detection, hidden attributes on Windows, date/size sorting, and navigation into directory symlinks. The current generation guard is good and must remain. [model generation handling](https://github.com/estyseesghosts/silvestris/blob/30173a5860ad263feacb3d417a73c3a354a21e78/crates/silvestris/src/file_panel/model.rs#L355-L425)

9. **P2 — Bound and simplify column-browser retained state.**  
   **Why this needs hardening:** FilePanel clones current entries into `browser_entries`, transforms them into `BrowserNode`s, and `ColumnBrowser::set_children()` clones the node vector into both its persistent `children` cache and an open column's controller. Late results are intentionally cached even after the column disappears. That is safe functionally, but repeated browsing can accumulate substantial duplicated state. [FilePanel browser construction](https://github.com/estyseesghosts/silvestris/blob/30173a5860ad263feacb3d417a73c3a354a21e78/crates/silvestris/src/file_panel/panel.rs#L1348-L1418) [ColumnBrowser cache duplication](https://github.com/estyseesghosts/silvestris/blob/30173a5860ad263feacb3d417a73c3a354a21e78/crates/silvestris/src/controls/column_browser.rs#L200-L225)  
   **Deliverables:** define what column data must stay cached. Retain the currently displayed path and perhaps a small recently-used set; evict branches that have been truncated and are no longer useful. Where practical, share immutable node collections instead of cloning whole vectors.  
   **Avoidables:** do not discard in-flight result safety—the comment about late answers not reopening truncated columns describes desirable behavior. Eviction must not allow a stale async completion to reconstruct old UI.  
   **Regression traps:** navigating left/right repeatedly, reopening a just-visited branch, async child loading, rename while a child column exists, preview state and selection survival.

10. **P2 — Turn filesystem affordances into real capabilities, not decorative promises.**  
   **Why this is incorrect:** removable locations are marked `eject`, FilePanel renders `RowAccessory::Eject`, but that accessory is just the ⏏ glyph. There is no action attached to it. That is especially problematic in a Cocoa/Finder-inspired picker because it visually communicates a control the user can operate. [FilePanel adds eject accessories](https://github.com/estyseesghosts/silvestris/blob/30173a5860ad263feacb3d417a73c3a354a21e78/crates/silvestris/src/file_panel/panel.rs#L429-L452) [Eject currently paints only a glyph](https://github.com/estyseesghosts/silvestris/blob/30173a5860ad263feacb3d417a73c3a354a21e78/crates/silvestris/src/controls/source_list.rs#L286-L315)  
   **Deliverables:** either add a real provider capability/action for eject/unmount and make the row accessory interactive, or stop rendering the eject glyph until that exists. Provider errors need to remain visible in the panel.  
   **Avoidables:** do not bake Windows/macOS/Linux unmount APIs into `SourceList`. The accessory is UI; `FileProvider` owns the capability.  
   **Regression traps:** clicking the accessory must not also select/navigate into the volume; keyboard/accessibility activation needs an equivalent path; failure to eject must leave the device visible.

The main architectural goal is to come out of this with a much cleaner division: **`ListController` owns efficient and correct generic collection state; the views render only visible material; `FilePanel` owns interaction policy and asynchronous operations; `FileProvider` owns filesystem identity and I/O.** Right now most of the rough edges come from those boundaries leaking into one another.

I would finish Tasks **1–4 before doing any more feature expansion on the panels**. Tasks **5–8** are what make the new real filesystem implementation trustworthy enough for Chaus to exercise heavily. Tasks **9–10** are important hardening, but they can follow once the core state/performance work is stable.
